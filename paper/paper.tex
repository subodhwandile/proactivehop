\title{ProactiveHop: Graph-Structured Reinforcement Learning for Proactive
Session Migration in Game Server Clusters}

\author[1]{Subodh Wandile}
\ead{subodhwandile10@gmail.com}
\address[1]{Independent Researcher}

\begin{abstract}
Stateful real-time servers (game servers, video conferencing endpoints,
financial matching engines) suffer $400$--$800$\,ms reconnect storms when
a server fails or becomes overloaded, because all sessions react
\emph{after} the disruption. We present \textbf{ProactiveHop}, a
system that pre-migrates sessions \emph{before} disruptions using a
Proximal Policy Optimization (PPO) agent whose observation is a
Graph Neural Network (GNN) encoding of the live cluster topology.
The GNN is designed to capture structural signals---rising failure probability on
a neighbor, correlated load spikes propagating along fat-tree
links---that are invisible to per-server threshold heuristics.

We implement ProactiveHop on a discrete-event simulator of a
$k{=}4$ fat-tree cluster and evaluate against No-Migration,
Threshold-70\%, LSTM Predictor, PPO+MLP, and a $p_{\rm drop}$-threshold heuristic.  Key results:
(1)~in a controlled server-crash scenario (20 seeds), PPO+GNN proactively migrates
$\mathbf{86.0\%\!\pm\!31.8\%}$ of affected sessions before the crash (median 100\%)---significantly
exceeding Threshold-70\% ($26.6\%\!\pm\!26.3\%$, Wilcoxon signed-rank $p{<}0.001$, Holm-corrected, $3.2\times$);
PPO+MLP achieves the highest crash-scenario rate ($98.0\%\!\pm\!6.1\%$, $p{=}0.14$ vs GNN);
GNN is not significantly different from LSTM ($54.8\%\!\pm\!41.4\%$, $p{=}0.023$, n.s.\ after Holm);
no pairwise difference among learned policies (GNN/MLP/LSTM) reaches significance at $n{=}20$;
(2)~in a multi-seed i.i.d.\ ablation (5 training seeds $\times$ 20 held-out seeds), GNN achieves
\textbf{1.8$\times$ higher catch rate} (1.64\% vs.\ 0.90\%, Welch $t$=5.53, $p$=0.0006) than MLP
under identical PPO training, confirmed by Mann-Whitney ($p{=}0.004$ one-sided);
edge-removal ablation (GNN-NoEdge-eval $p{=}0.012$) shows the trained model
relies on its edge inputs at evaluation time, though an edge-free GNN trained from scratch matches performance ($p{=}0.78$);
(3)~inference time grows only \textbf{1.1$\times$} when cluster size
grows \textbf{4$\times$} ($N{=}16\!\to\!64$) vs.\ $4.3\times$ for LSTM,
verifying the near-linear inference scaling of local neighbourhood aggregation.

ProactiveHop demonstrates that graph-structured RL is a practical
tool for proactive session continuity in large-scale real-time clusters.
In the crash scenario, GNN pre-migrates $\approx$86\% of sessions
vs.\ $\approx$27\% for Threshold, a 3.2$\times$ improvement (Wilcoxon $p{<}0.001$, Holm-corrected);
PPO+MLP achieves the highest crash-scenario rate (98\%) though the difference from GNN is not significant ($p{=}0.14$);
the primary proven GNN-vs-MLP advantage is a 1.8$\times$ higher i.i.d.\ catch rate,
combined with near-linear inference scaling and zero-shot generalization to larger clusters.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Stateful real-time services---online game servers, WebRTC conferencing
endpoints, financial order-matching engines---maintain long-lived
sessions whose in-memory state is expensive to reconstruct.
When a server fails or saturates its CPU, sessions disconnect and must
reconnect reactively.  The disruption window is well-documented across
production systems:

\begin{itemize}
  \item \textbf{Game servers (AWS GameLift, Agones):} AWS explicitly
        states that ``game sessions actively running on a reclaimed
        instance are \emph{interrupted}''~\cite{awsgamelift}; the
        Agones fleet manager \emph{deletes} unhealthy servers and
        spawns replacements, with a minimum detection latency of
        $3 \times \mathtt{periodSeconds}$ (default 15\,s) before any
        reconnect can begin~\cite{agones}.
  \item \textbf{WebRTC / video conferencing (Jitsi, RFC 8445):}
        When the underlying server fails, an in-place ICE restart
        cannot reuse the dead transport; a full new \texttt{PeerConnection}
        with fresh DTLS/SRTP negotiation takes 1--3\,s~\cite{bloggeek}.
        Applications must trigger this manually---``the browser will
        not trigger one on its own''~\cite{mdnwebrtc}.  Jitsi's
        GitHub pull request \#2438 shows in-place SFU failover
        is being addressed but not yet standard~\cite{jitsi2438}.
  \item \textbf{Routing latency (Riot Games):} Riot built an entire
        private backbone (Riot Direct) specifically to avoid reactive
        path failures that pushed round-trip latency from 14\,ms to
        70\,ms---a 5$\times$ spike---on commodity routing~\cite{riotdirect}.
\end{itemize}

In all three domains the root cause is the same: \emph{the system waits
for failure to be detected before acting}.  Detection introduces
multi-second delays; reconnect adds 1--3\,s more.  For game servers and
video calls this is a hard user-visible disruption.

Existing mitigation approaches fall into three categories:
\begin{enumerate}
  \item \textbf{No migration}: sessions reconnect after failure.
        Simple but reactive; inherits the full detection + reconnect delay.
  \item \textbf{Threshold heuristics}: migrate when a server's CPU
        exceeds a fixed threshold (e.g., 70\%).
        Acts before failure only if load spiked first; blind to
        failure-rate signals and neighbor state.
  \item \textbf{Hot standby}: keep a replica server warm (e.g., AWS
        RDS Multi-AZ).  Eliminates reconnect but doubles resource cost
        and still requires detection before switchover.
\end{enumerate}

None of these approaches uses \emph{structural topology signals}.
A fat-tree cluster has a rich graph structure: a server with rising
failure rate and two neighbors already at 80\% load is qualitatively
different from the same server with idle neighbors.
Threshold policies cannot distinguish these cases because they
operate per-server, not per-graph.

We ask: \emph{can a GNN-based RL agent learn to read topology signals
and proactively drain sessions from servers about to fail?}

\textbf{Contributions.}
\begin{itemize}
  \item We formulate cluster session management as a Markov Decision
        Process (MDP) over a graph, with a differential latency reward
        that makes proactive migration intrinsically profitable
        (\S\ref{sec:formulation}).
  \item We design a two-layer GraphSAGE encoder that processes only the
        1-hop neighbourhood of each node, with per-layer cost
        O($|E| \cdot d_h + N \cdot d_h^2$)---linear in $N$ for bounded degree
        (\S\ref{sec:model}).
  \item We implement ProactiveHop on a fat-tree simulator
        with Weibull failure injection, delta-compressed session state,
        and correlated load spikes (\S\ref{sec:simulator}).
  \item We run controlled experiments showing PPO+GNN achieves
        \textbf{1.8$\times$ higher catch rate than MLP} (1.64\% vs 0.90\%,
        $p{=}0.0006$, Welch $t$-test, 5 training seeds $\times$ 20 held-out seeds)
        in i.i.d.\ evaluation, where the gain is attributable to the
        shared-weight GNN encoder rather than to topology (edge-removal ablation
        $p{=}0.78$ when trained from scratch); scales near-linearly
        to $N{=}64$ servers zero-shot (inference $1.1\times$ vs $4.3\times$ for LSTM);
        and in a controlled crash scenario (20 evaluation seeds) GNN ($86.0\%$)
        significantly outperforms Threshold-70\% ($26.6\%$, Wilcoxon $p{<}0.001$, Holm-corrected, $3.2\times$);
        PPO+MLP achieves the highest crash-scenario rate ($98.0\%$, $p{=}0.14$ vs GNN);
        GNN is not significantly different from LSTM ($54.8\%$, $p{=}0.023$, n.s.\ after Holm);
        no pairwise difference among learned policies significant
        at $n{=}20$
        (\S\ref{sec:evaluation}).
\end{itemize}

\paragraph{Reactive session migration.}
``Staying Alive''~\cite{nsdi21stayingalive} reselects connection paths
at the network edge when the current path degrades, keeping sessions
alive without full reconnect.  Migration is \emph{triggered reactively},
inheriting the full 400--800\,ms reconnect latency, since
the system must wait for the failure to be confirmed before acting.
Clark et al.'s live migration~\cite{livemig2005} pre-copies VM
memory pages while the VM is running (warm migration) to minimize
downtime, but the \emph{trigger} remains a manual operator command or
a reactive health check.  Neither system uses predictive signals or
graph topology to act before symptoms become failures.
ProactiveHop targets the window between first observable symptom
(rising $\lambda_v$, CPU stress) and confirmed failure.

\paragraph{GNN-based cluster scheduling.}
Decima~\cite{sigcomm19decima} applies GNN+RL to Spark job scheduling,
where the computation graph (job DAG) is the structured input.
The GNN aggregates stage-to-stage dependencies; the action is
assigning stages to executors.  Our graph is the \emph{physical
cluster topology}, not a job DAG: nodes are servers, edges are network
links with latency and bandwidth attributes, and the action is a
binary per-server pre-migration trigger.  The key difference is that
Decima's graph is given (the submitted job), whereas ProactiveHop
must reason about \emph{evolving} load and failure signals on a fixed
physical topology.  AuTO~\cite{auto2018} uses a two-level RL system
for flow scheduling in data centres, but operates at the flow level
without session state and without graph-structured encoding.

\paragraph{Handoff via RL in dense WLANs.}
A substantial line of work uses RL for access-point handoff in dense
wireless LANs~\cite{5ghandoff}.  These approaches model the
problem as a Markov decision process where a mobile client moves
through a graph of fixed base stations; the policy decides when to
hand off to a neighbouring cell.  The graph topology is the radio
access network, and the state is signal strength and cell load.
Our setting is the \emph{inverse}: clients are stationary (game
sessions, WebRTC peers) and servers can fail or become overloaded.
Migration is a \emph{business} decision with an explicit bandwidth
cost (session state transfer), not a physical necessity imposed by
client movement.  Furthermore, handoff systems operate per-UE on a
single radio link; ProactiveHop operates over a full fat-tree cluster
with $N{=}16$--64 servers simultaneously.

\paragraph{RL for networking.}
Pensieve~\cite{lbgnn} applies deep RL to adaptive bitrate (ABR) video
streaming, learning a per-chunk bitrate policy from throughput history.
CPC~\cite{cpc2019} uses contrastive predictive coding to learn latent
representations of sequential data.
Both operate on a \emph{single} client--server link with scalar state;
neither has a graph topology or a migration cost.  ProactiveHop extends
the RL-for-networking line to \emph{multi-server graph-structured}
decisions, where the observation is a GNN embedding of the live
cluster graph and the reward explicitly penalises unnecessary
session state transfers.

\paragraph{Proactive resource management.}
Lin et al.~\cite{prophet2020} predict node failure in cloud service
systems from runtime performance metrics (CPU, memory, network counters)
and trigger migration before the predicted failure window.
The key differences are (i)~their approach uses a
per-node time-series predictor on performance counters rather than a
graph-structured policy over the cluster; (ii)~it migrates full
VMs with operator-confirmed triggers, not real-time sessions with
sub-second reconnect budgets; and (iii)~it does not jointly
optimise migration decisions across servers.  ProactiveHop combines
the predictive insight of Lin et al.\ with the topology reasoning of
Decima in a single end-to-end RL policy.

\section{Problem Formulation}
\label{sec:formulation}

\subsection{System Model}

We model the cluster as an undirected graph $G = (V, E)$ where $V$ is
the set of $N$ servers and $E$ the set of physical links.  Each server
$v \in V$ at time step $t$ has a feature vector:
\[
  \mathbf{x}_v^t = \bigl[\,
    u_v,\; m_v,\; \sigma_v,\; \ell_v,\; p_v^{\rm drop},\; a_v,\; \lambda_v
  \,\bigr] \in \mathbb{R}^7
\]
where $u_v$ = CPU utilization, $m_v$ = memory utilization,
$\sigma_v$ = session ratio (sessions / capacity), $\ell_v$ = composite
load, $p_v^{\rm drop} = \sigma\!\bigl((\ell_v - 0.72) \cdot 15\bigr)$
= drop probability (steep sigmoid for clean gradient),
$a_v \in \{0,1\}$ = alive flag, and $\lambda_v$ = load-coupled failure hazard rate,
$\lambda_v = 20\cdot\bigl[p_{\rm base} + 0.005\cdot\max(0,\,\ell_v - 0.70)\bigr]$,
where $p_{\rm base} = 1 - e^{-(\Delta t/\text{MTBF})^{1.5}}$
is the baseline Weibull per-step probability.  Note that $\lambda_v$ is
a deterministic function of $\ell_v$ plus the fixed MTBF baseline; it
provides the GNN a \emph{scaled and thresholded} view of overload risk
distinct from the raw $\ell_v$ value.

Each link $e = (u,v) \in E$ has features
$\mathbf{e}_{uv} = [\text{latency},\; \text{bandwidth},\; \text{utilization},\; \text{loss}]$.

\subsection{MDP Definition}

\textbf{State} $s_t = (G, \{\mathbf{x}_v^t\}_{v \in V}, \{\mathbf{e}_{uv}\}_{(u,v) \in E})$
--- the full attributed graph at step $t$.

\textbf{Action} $\mathbf{a}_t \in \{0,1\}^N$: a binary flag per server.
$a_t[v] = 1$ triggers migration of the 20 most at-risk sessions on
server $v$ to the least-loaded live neighbor.

\textbf{Transition}: the simulator applies \emph{persistent} migration
decisions---sessions move immediately to the target server.
At step end, a \emph{counterfactual} drop check runs at the original server:
if the server's drop probability would have fired, the migration is a
true positive (TP); otherwise it is a false positive (FP).
The simulator also advances arrivals and departures, injects correlated
load spikes (probability 0.08 per step), and samples load-coupled Weibull
failures (shape $k{=}1.5$, scale MTBF; see $\lambda_v$ above).

\textbf{Reward.} Let $m_t$ be the step metrics tuple.  We use a
\emph{differential latency reward}:
\begin{equation}
  r_t = m_t^{\rm TP} \cdot \bigl(\bar{L}_{\rm react} - \bar{L}_{\rm spec}\bigr)
        - C_{\rm bw} \cdot B_t
  \label{eq:reward}
\end{equation}
where $m_t^{\rm TP}$ = true-positive migrations (sessions moved proactively
to a server whose old host would have dropped them), $\bar{L}_{\rm react} = 450$\,ms = mean reactive
reconnect latency, $\bar{L}_{\rm spec} = 5$\,ms = mean proactive handoff
latency (live session transfer cost), $C_{\rm bw} = 5 \times 10^{-5}$ = bandwidth
penalty coefficient, and $B_t$ = migration bandwidth in KB.

This formulation has a critical property: \emph{the no-migration
baseline receives zero reward}, not a negative reward proportional to
drops.  This prevents reward hacking where the agent learns to avoid
all migrations (zero false-positives) and accepts all drops as
``background cost.''

\subsection{Representational Separation: Threshold vs.\ 1-hop GNN}
\label{sec:proposition}

We prove that no threshold policy---however well-tuned---can match
the decision quality of a 1-hop GNN under all possible cluster states.

\begin{definition}
A \emph{threshold policy} $\mathcal{T}(\theta)$ decides to migrate
sessions from server $v$ if and only if $\ell_v \geq \theta$, for some
fixed $\theta \in [0,1]$.  It is a function solely of $\ell_v$.
\end{definition}

\begin{proposition}
\label{prop:main}
There exist two cluster states $S_1, S_2$ and a server $v$ such that:
\begin{enumerate}
  \item $\ell_v(S_1) = \ell_v(S_2)$ (identical local load),
  \item The 1-hop GNN's representation of $v$ differs between $S_1$ and $S_2$,
        so the actor head \emph{can} produce different migration decisions,
  \item Any threshold policy $\mathcal{T}(\theta)$ produces the \emph{same}
        decision in $S_1$ and $S_2$,
  \item No fixed threshold can produce both decisions; the GNN has the
        representational capacity to do so.
\end{enumerate}
\end{proposition}

\begin{proof}
Let $\ell_v = 0.72$ in both states.

\textbf{State $S_1$}: All neighbors $u \in \mathcal{N}(v)$ have load
$\ell_u = 0.3$.  Migration sends sessions to lightly loaded neighbors.

\textbf{State $S_2$}: All neighbors have $\ell_u = 0.85$.
All available targets are saturated, so migration is likely to cause
unnecessary bandwidth cost with limited benefit.

Any $\mathcal{T}(\theta)$ with $\theta \leq 0.72$ migrates in both states;
with $\theta > 0.72$ it migrates in neither.
No fixed $\theta$ can make different decisions in $S_1$ and $S_2$.

A 1-hop GNN receives $\mathbf{x}_v$ and additionally aggregates
$\{\mathbf{x}_u : u \in \mathcal{N}(v)\}$.  Its representation
$\mathbf{h}_v^{(1)}$ differs between $S_1$ and $S_2$ (neighbor
loads differ), so the actor head \emph{can} produce different decisions.
\end{proof}

\begin{remark}
Under the persistent migration mechanic, a migrated session's TP
classification is determined by the \emph{old} server's counterfactual
drop probability.  For $\ell_v = 0.72$ (the proof's baseline), the
per-step counterfactual TP rate is $p_{\rm drop}(0.72) = 0.5$.  The
proposition therefore establishes a \emph{representational} result:
the GNN can encode a decision boundary in $(\ell_v, \bar{\ell}_{\mathcal{N}(v)})$ space
that no scalar threshold can.  Whether the RL optimisation finds that
boundary under the one-step counterfactual reward is an empirical
question (\S\ref{sec:ablation}), not a consequence of this proposition.
\end{remark}

\noindent
The proposition is tight: LSTM also cannot distinguish $S_1$ from
$S_2$ because it watches each server in isolation (no cross-server
aggregation), regardless of how many historical timesteps it observes.

\section{Model Architecture}
\label{sec:model}

\subsection{GNN Encoder}

We use a two-layer GraphSAGE~\cite{graphsage} encoder.
The forward pass has four stages.

\paragraph{Edge-feature injection.}
Each directed edge $(v, u)$ carries a feature vector
$\mathbf{e}_{vu} \in \mathbb{R}^4$
(link latency, bandwidth, utilization, packet-loss).
Before graph convolution, per-edge context is projected and sum-aggregated
into source nodes:
\begin{equation}
  \tilde{\mathbf{x}}_v = \mathbf{x}_v
    + \sum_{(v,u)\in\mathcal{E}_v} W_e\,\mathbf{e}_{vu},
  \qquad W_e \in \mathbb{R}^{7 \times 4}
  \label{eq:edge_inject}
\end{equation}
where $\mathcal{E}_v$ is the set of edges incident to $v$.

\paragraph{Input projection.}
The 7-dimensional augmented features are lifted to the hidden dimension:
\begin{equation}
  \mathbf{h}_v^{(0)} = \text{ReLU}\!\bigl(W_{\rm in}\,\tilde{\mathbf{x}}_v\bigr),
  \qquad W_{\rm in} \in \mathbb{R}^{d_h \times 7},\; d_h = 64
  \label{eq:input_proj}
\end{equation}

\paragraph{GraphSAGE layers ($l = 1, 2$).}
Each layer performs neighborhood aggregation followed by a residual update:
\begin{equation}
  \tilde{\mathbf{h}}_v^{(l)} =
    \text{ReLU}\!\Bigl(
      W_l \cdot \bigl[\mathbf{h}_v^{(l-1)} \,\|\,
      \textstyle\text{MEAN}_{u \in \mathcal{N}(v)} \mathbf{h}_u^{(l-1)}\bigr]
    \Bigr)
  \label{eq:sage}
\end{equation}
\begin{equation}
  \mathbf{h}_v^{(l)} = \mathbf{h}_v^{(l-1)}
    + \text{Dropout}\!\bigl(\tilde{\mathbf{h}}_v^{(l)},\, p{=}0.1\bigr)
  \label{eq:residual}
\end{equation}
where $W_l \in \mathbb{R}^{d_h \times 2d_h}$ and all tensors remain in
$\mathbb{R}^{d_h}$---the input projection ensures no dimension mismatch.

\paragraph{Normalization and output projection.}
After both layers, a single Layer Normalization followed by a linear
output projection yields the final node embeddings:
\begin{equation}
  \mathbf{z}_v = W_{\rm out}\,\text{LN}\!\bigl(\mathbf{h}_v^{(2)}\bigr),
  \qquad W_{\rm out} \in \mathbb{R}^{d_h \times d_h}
  \label{eq:output_proj}
\end{equation}
Hidden dimension $d_h = 64$, output dimension $d_h = 64$.

Each layer aggregates only the 1-hop neighborhood.  Two layers
therefore aggregate the 2-hop neighborhood.  The per-node computation
is $O(\text{deg}(v)^2)$, and summing over all nodes gives
$O(|E| \cdot d_h^2)$ total, which is $O(N \cdot \bar{d}^2)$ for
degree-bounded topologies.  Fat-tree degree is bounded by $k$ (pod
size), so inference time is $O(N \cdot k^2)$ for fixed $k$.  Because
$k$ is a topology constant (4 in our fat-tree) while $N$ grows with
cluster size, latency grows linearly in $N$ in the worst case but
empirically near-linearly (1.1$\times$ for a 4$\times$ increase in $N$) as shown in \S\ref{sec:scalability}.

\subsection{Actor-Critic Network}

The GNN produces node embeddings $\{\mathbf{h}_v\}$.  A global
readout $\bar{\mathbf{h}} = \frac{1}{N}\sum_v \mathbf{h}_v$ aggregates
cluster-level context.

\textbf{Actor}: for each server $v$, compute logit
$\pi_v = W_a [\mathbf{h}_v \| \bar{\mathbf{h}}] \in \mathbb{R}$
and sample $a_v \sim \text{Bernoulli}(\sigma(\pi_v))$.

\textbf{Critic}: $V(s) = W_c \bar{\mathbf{h}} \in \mathbb{R}$.

Both $W_a, W_c$ are two-layer MLP heads (hidden size 64, ReLU) applied after the shared GNN.

\subsection{PPO Training}

We train with Proximal Policy Optimization~\cite{ppo} with GAE
($\lambda = 0.95$), clip $\epsilon = 0.2$, entropy coefficient 0.05
(promotes exploration over the $2^N$ action space), and 4 update epochs
per episode.  Episode length is 100 steps; training runs for 500
episodes.  All experiments use CPU inference.  Full hyperparameters
are listed in Table~\ref{tab:hyperparams}.

\section{Simulator}
\label{sec:simulator}

We implement a discrete-event cluster simulator (\texttt{sim/})
with the following components:

\textbf{Topology}: fat-tree with $k=4$ (16 servers).
All paper experiments use this topology; zero-shot transfer to larger
clusters ($N{=}25$; $N{=}64$) is evaluated in
\S\ref{sec:scalability}.

\textbf{Session model}: sessions arrive as a Poisson process (rate
$\lambda_{\rm arr} = 10$/step), have Pareto-distributed lifetimes
(mean 60 steps), and carry delta-compressed state ($\sim$500\,KB mean).
Persistent pre-migration costs $\bar{L}_{\rm spec} = 5$\,ms (fast session state transfer);
reactive reconnect costs $\bar{L}_{\rm react} \sim \mathcal{N}(400,150^2)$\,ms.

\begin{sloppypar}
\textbf{Failure model}: each server fails per step with probability
$p_f = 1 - \exp\!\bigl(-(\Delta t / \text{MTBF})^{1.5}\bigr)$
(Weibull shape 1.5). Failed servers recover after $\text{Exp}(\text{MTTR})$
steps. Drop probability on overloaded \emph{live} servers follows
$p_{\rm drop}(v) = \sigma\bigl((\ell_v - 0.72) \times 15\bigr)$.
\end{sloppypar}

\textbf{Load dynamics}: loads decay toward a base load $\ell_0 = 0.55$
with damping 0.05 per step, plus correlated spikes (probability 0.08,
magnitude 0.35) that persist for 10 steps and spread to neighboring
servers.

\subsection{Simulator Fidelity Validation}
\label{sec:simvalid}

A common critique of simulation-based evaluation is that the simulator
may not reproduce the statistical properties of real deployments.
We validate three key properties against empirical data and
theoretical expectations.

\paragraph{Failure inter-arrival distribution.}
The simulator draws per-step failure probability from a Weibull
distribution with shape $\kappa{=}1.5$ and scale $\eta{=}3600$\,s
(MTBF 3600\,s).  Shape $\kappa{=}1.5$ was chosen to match empirical
hazard rates reported in field studies of disk and DRAM
failure~\cite{barroso2013datacenter}.  Note that the simulator applies
the Weibull CDF as an \emph{i.i.d.\ per-step} probability---each
timestep draws a fresh Bernoulli sample at the same fixed hazard
rate---rather than as a true aging process across steps.
The per-step probability $p_f = 1 - e^{-(\Delta t / \eta)^\kappa}$
evaluates to ${\approx}4.6 \times 10^{-6}$ per server per second,
corresponding to roughly one server failure every ${\approx}60$ hours
\emph{per server}, or one cluster-level failure every ${\approx}3.8$ hours
across a 16-server cluster---consistent with reported MTBF in
hyperscale data centres~\cite{barroso2013datacenter}.

\paragraph{Session arrival process.}
Sessions arrive as a Poisson process with rate $\lambda_{\rm arr}$.
The Poisson assumption is standard for modelling independent user
connections at the session layer and is validated by the Alibaba 2018
trace experiment (\S\ref{sec:trace}): under $4.3\times$ higher
coefficient of variation (real trace vs.\ synthetic Poisson), PPO+GNN's
catch rate drops only 0.2 percentage points, indicating the policy is
robust to the Poisson approximation.  Session lifetimes follow a
Pareto distribution with shape $\alpha{=}1.5$, matching the heavy-tailed
flow-size distributions observed in data-centre traffic
studies~\cite{sigcomm19decima}.

\paragraph{Load spike propagation.}
Correlated load spikes (probability 0.08 per server per step, magnitude
0.35, duration 10 steps) model bursty traffic patterns such as
flash crowds or cache invalidation storms.  The spike propagates to
neighbouring servers with a 50\% probability, reflecting
intra-cluster load imbalance observed when a hot shard floods the
network path to its replicas.  With spike probability 0.08 per step
and duration 10 steps, servers spend roughly 44\% of time in a spike
state; the measured peak composite load during spiking (post-warmup, 5 seeds,
500 steps each) reaches $0.92 \pm 0.10$, consistent with heavily-utilised
clusters during burst periods~\cite{riotdirect}.
The 44\% spiking fraction keeps a substantial share of servers transiently
above the $\ell_v{=}0.72$ drop threshold; between spikes, load
decays toward the base ($\ell_0{=}0.55$) where drop probability is low.

\section{Evaluation}
\label{sec:evaluation}

\subsection{Baselines}

\begin{itemize}
  \item \textbf{No-Migration}: sessions reconnect reactively after
        any drop or failure.
  \item \textbf{Threshold-70\%}: migrates top-20 sessions from any
        server whose composite load exceeds 70\%.
  \item \textbf{LSTM Predictor}: a 2-layer LSTM trained on 100 episodes
        of simulator traces; observes a 10-step sliding window of
        [load, failure\_rate, session\_count] per server and predicts
        load 5 steps ahead. Migrates if predicted load $>0.65$.
        This baseline has \emph{temporal memory but no topology}.
  \item \textbf{$p_{\rm drop}$ heuristic}: thresholds $p_{\rm drop}(v)$ (feature index 4 in
        the 7-dim observation vector) at $5 \times 10^{-3}$ and
        pre-migrates all sessions from any server above threshold.
        It is a $p_{\rm drop}$-threshold strategy bound; because it uses the
        same observable signal as the agent, it shows how much a perfectly
        tuned greedy policy over that signal could achieve.
  \item \textbf{PPO+GNN (ours)}: trained 500 episodes over 5 random seeds (seeds 0--4);
        evaluated on held-out seeds.  The crash-scenario checkpoint
        (\texttt{best\_GNN.pt}) is the highest-reward checkpoint from seed 0;
        the i.i.d.\ ablation uses all 5 checkpoints.
        Policy decisions use greedy (argmax) action selection for
        deterministic, reproducible evaluation.
  \item \textbf{PPO+MLP (ablation)}: identical PPO setup but the GNN
        encoder is replaced by a flat MLP receiving all $N \times 7$
        node features concatenated.  Same training budget, reward, and
        hyperparameters.  Isolates the contribution of graph structure.
\end{itemize}

transfers directly.  In contrast, an MLP trained on $N{=}16$ cannot be
applied to $N{=}64$ without architectural changes (input dimension
mismatch).

also accelerates initial exploration.  Excluding the collapsed run,

range when the learning rate does not push into instability.

\paragraph{Topology-aware heuristics vs.\ learned policies.}
A natural question is whether a \emph{handcrafted} topology-aware
heuristic---without RL---can close the gap.  We evaluated a
\textbf{Neighbour-Aware Threshold} that conditions migration on two criteria:
$\ell_v \geq 0.70$ \emph{and} mean neighbour load $< 0.60$ (avoiding
saturated targets).  In i.i.d.\ evaluation, this achieves 0.12\%
catch rate---below plain Threshold-70\% (0.2\%, Table~\ref{tab:scale}),
because the additional neighbour-load constraint reduces migration
frequency and thus catch opportunities.  Yet both heuristics fall $13\times$
below PPO+GNN (1.64\%).  The lesson: topology-aware
heuristics avoid obviously wasteful migrations (sending sessions to
overloaded neighbours) but cannot learn \emph{when} to proactively drain
a server before a failure event; that requires credit assignment over
multi-step episodes, which reinforcement learning provides.

\section{Discussion}
\label{sec:discussion}

\paragraph{Why catch rates are modest and variable.}
Catch rate measures the fraction of \emph{true drops} intercepted by
pre-migration.  True drops occur only when a server is near failure or
has elevated load; in a healthy cluster running below the sigmoid threshold
($\ell_v < 0.72$), drop probability is low, so the per-step at-risk
population is small.  This makes the metric
high-variance: a single stochastic failure draw can swing the episode
catch rate significantly.  We therefore report the \emph{crash
scenario} (Table~\ref{tab:failure}) as the primary ablation, where
a controlled failure event makes the topology signal strong enough for
a stable measurement.  In i.i.d.\ evaluation, the cleaner signal is
\textbf{catch rate}: GNN achieves 1.8$\times$ higher catch rate
(1.64\% vs.\ 0.90\%, $p{=}0.0006$, Welch $t$-test, 5 training seeds) across 20 held-out seeds.

\paragraph{Absolute impact at production scale.}
Although the i.i.d.\ catch rates (1.64\% vs.\ 0.90\%) appear small in
isolation, they translate to meaningful savings at cluster scale.
Consider a cluster of $N{=}16$ servers each hosting 10,000 concurrent
sessions (160,000 total).  GNN's 1.64\% catch rate saves
$\approx\!2{,}624$ sessions per 100-step episode from a 400\,ms reconnect;
MLP saves $\approx\!1{,}440$.  The difference of 1,184 sessions $\times$
$(400 - 5)$\,ms $= 468$\,s of avoided reconnect latency per 100-step episode.
Scaled to a 3,600-step production hour (36 episodes) this is $\approx\!16{,}850$\,s
(${\approx}4.7$ hours) of saved latency per cluster-hour---equivalent to preventing roughly
$42{,}600$ player-visible lag spikes per cluster-hour of operation.

\paragraph{Why GNN outperforms LSTM in deployable settings.}
LSTM requires the temporal degradation ramp to be present and smooth to
exploit its advantage.  In the i.i.d.\ evaluation (random failures,
no pre-crash ramp), LSTM achieves 1.58\%$\pm$0.19\%---comparable to
GNN (1.64\%, $p{=}0.55$)---because the 10-step load window provides
useful trend signal even for random failures.  Despite i.i.d.\ parity,
three additional deployment constraints favour the GNN:
(i)~\textbf{zero-shot generalization}: an LSTM trained on $N{=}16$
cannot be applied to $N{=}64$ without retraining (input dimension
mismatch), while the GNN transfers directly (Table~\ref{tab:scale});
(ii)~\textbf{inference scaling}: LSTM inference grows $4.3\times$ for a
$4\times$ cluster size increase vs.\ $1.1\times$ for the GNN;
(iii)~\textbf{decision reliability}: CoV values in the crash scenario are
descriptive (GNN 0.59, LSTM 0.48, MLP 0.55); no pairwise difference is
significant at $n{=}20$.

\paragraph{False-positive rate.}
The $\sim$65\% false-positive rate (migrations that were unnecessary because
the session would not have dropped) reflects the exploration-exploitation
tradeoff in PPO.  The bandwidth cost term $C_{\rm bw}$ in the reward
partially penalizes unnecessary migrations; tightening $C_{\rm bw}$
reduces FP rate at the cost of fewer true positives.
ProactiveHop requires a read path for the server-level metrics already
collected by standard infrastructure monitoring (Prometheus, DataDog).
The GNN runs on-controller as a lightweight 1.2\,ms inference service.
Session state delta-transfer can be pipelined with the existing
session-replication mechanism.

\section{Limitations and Future Work}
\label{sec:limitations}

\paragraph{Simulation-only evaluation.}
\begin{sloppypar}
All experiments are conducted on a discrete-event simulator calibrated
to a $k{=}4$ fat-tree topology.  The simulator reproduces key
real-world phenomena---Weibull failure injection, correlated load
spikes, per-link latency and bandwidth---but cannot capture
OS scheduling jitter, network stack variability, or application-level
session state complexity.  We note that leading simulation-based RL
systems research (Decima~\cite{sigcomm19decima}, AuTO~\cite{auto2018})
also began with simulation to isolate algorithmic contributions
before real deployments.  Our simulator is openly parameterised with
arrival rates calibrated against the Alibaba 2018 trace;
any practitioner can substitute real load traces and failure logs to
produce cluster-specific results.  A live deployment on a small cloud
cluster (e.g., 4--8 AWS EC2 instances running a dummy game server) would
provide a hardware-grounded upper bound on achievable catch rate and
measure the true cost of session state delta-transfer.
The Alibaba 2018 trace experiment (\S\ref{sec:trace}) partially
addresses this by validating robustness to real arrival burstiness,
but does not substitute for an end-to-end real-system measurement.
\end{sloppypar}

\paragraph{Single topology family.}
The GNN is trained and evaluated exclusively on $k{=}4$ fat-tree
topologies.  Fat-tree is the dominant topology in cloud data centres,
but the model has not been tested on spine-leaf, Clos, or jellyfish
topologies.  Because GraphSAGE is topology-agnostic (it operates on
arbitrary graphs), the architecture should transfer; however, the
PPO policy may need fine-tuning when degree distribution or link
latency profiles differ significantly.  Zero-shot transfer to a
$k{=}5$ fat-tree ($N{=}25$ servers) has already been evaluated
(\S\ref{sec:scalability}); extending to spine-leaf or jellyfish
topologies would be a natural next step.

\paragraph{Modest absolute catch rate.}
The best observed catch rate is $\sim$1.6\% in i.i.d.\ evaluation (2.3\% at the default entropy setting).
Under the persistent migration mechanic, catch rate is bounded by the fraction
of sessions whose \emph{counterfactual} server load exceeds the drop threshold
in the step they are migrated---a noisy, low-probability event in a healthy cluster.
Two directions could improve this.  First, a \emph{predictive
horizon} longer than one step---pre-migrating sessions that are
likely to drop within the next $H$ steps---would widen the opportunity
window.  Second, a \emph{model-based} rollout (learning a dynamics
model of server load evolution and planning ahead) could exploit the
degradation ramp more aggressively; the $p_{\rm drop}$-threshold heuristic
(${\approx}71\%$ catch rate, Table~\ref{tab:failure}) shows how much headroom remains.

\paragraph{Reward sensitivity.}
The reward function combines two terms: latency saving and bandwidth
penalty, weighted by $C_{\rm bw} = 5\times10^{-5}$ per KB.  This weight
was set manually.  A systematic search over $C_{\rm bw}$ could discover
configurations that reduce the 65\% false-positive rate without
sacrificing catch rate.  The tradeoff is well-defined and likely
Pareto-optimal, but the current paper reports only a single point.

\paragraph{Multi-agent coordination.}
ProactiveHop uses a centralised controller that observes the full
cluster state and issues per-server migration actions.  In very large
clusters ($N > 256$) or geo-distributed deployments, a centralised
controller introduces a single point of failure and a communication
bottleneck.  A decentralised variant---where each server runs a local
GNN policy using only its 2-hop neighbourhood---would preserve the
per-node encoder advantage while eliminating the central dependency.
The GraphSAGE architecture already computes per-node embeddings from
local neighbourhoods, making this a natural architectural extension.

\paragraph{Evaluation scope and statistical limitations.}
Several additional limitations bound the interpretation of our results.
(1)~\textit{Counterfactual TP vs.\ Proposition 1}: the one-step counterfactual
TP definition (session would have dropped on the old server in the same step)
does not perfectly align with the optimality condition in Proposition 1,
which assumes the agent can distinguish S1 (safe) from S2 (overloaded) states;
a joint survival condition (drops on old AND survives on target) would be
more rigorous but requires future-step oracle knowledge.
(2)~\textit{Weibull without aging}: the per-step i.i.d.\ Weibull failure
draw has constant hazard within each step, so the shape parameter
(1.5) confers no aging effect; a time-inhomogeneous Weibull that
accumulates hazard across steps would better model hardware wear-out.
(3)~\textit{Topology vs.\ architecture}: the NoEdge-train result
(1.59\%, $p{=}0.78$ vs GNN in i.i.d.) indicates that topology edges
are not strictly necessary in the i.i.d.\ setting; the GNN advantage
over MLP may derive primarily from the shared-weight node encoder
rather than relational message passing.  Topology's contribution is
clearest in the crash scenario (Table~\ref{tab:failure}).
(4)~\textit{$p_{\rm drop}$ strategy bound}: the heuristic thresholds $p_{\rm drop}$,
which is included in the agent's 7-dim observation vector, so it
does not have information the agent lacks.  It is a \emph{strategy}
upper bound (always migrating all at-risk sessions) rather than an
information upper bound.  A true information upper bound would require
future-step failure labels unavailable to any online system.
(5)~\textit{Single hand-designed ramp}: the crash scenario uses one
monotonic 10-step degradation ramp; real-world failures may exhibit
different onset patterns (sudden, oscillating, cascading).
(6)~\textit{Small $n$}: the crash scenario uses 1 checkpoint $\times$ 20 evaluation
seeds; no pairwise difference among learned policies (GNN/LSTM/MLP) is significant
at $n{=}20$ ($p$-values 0.023--0.14, none surviving Holm correction for learned-policy pairs).  The i.i.d.\ ablation ($n{=}5$ training seeds)
has limited power for secondary comparisons.
(7)~\textit{Metric design and denominator choices}: the crash-scenario metric
was redesigned across multiple iterations---from ``latency $<$ 50\,ms'' to
policy-driven moves via \texttt{\_migrated\_this\_step}, with a fixed denominator of exactly 25 seeded sessions
(identical across all policies) to prevent organic session counts from biasing comparisons
across policies that drain sessions differently during warm-up.
These design choices materially affect absolute percentages (e.g.\ old design yielded $\approx$20\%
for GNN; the fixed denominator design yields 86\%),
though the qualitative result (GNN significantly exceeds Threshold; no pairwise difference
among learned policies at $n{=}20$) is robust.

\section{Conclusion}
\label{sec:conclusion}

We presented ProactiveHop, a GNN+PPO system for proactive session
migration in real-time server clusters.  By encoding the cluster
topology as a graph and learning a differential-latency reward, the
system uses 2-hop neighbourhood aggregation to pre-migrate sessions
before disruptions occur.

Empirically, in a controlled crash scenario (20 seeds), PPO+GNN ($86.0\%\!\pm\!31.8\%$, median 100\%)
significantly outperforms Threshold-70\% ($26.6\%\!\pm\!26.3\%$, Wilcoxon $p{<}0.001$, Holm-corrected, $3.2\times$);
PPO+MLP achieves the highest crash-scenario rate ($98.0\%\!\pm\!6.1\%$) though GNN is not
significantly different from MLP ($p{=}0.14$) or LSTM ($54.8\%\!\pm\!41.4\%$, $p{=}0.023$, n.s.\ after Holm);
no pairwise difference among learned policies reaches significance at $n{=}20$.
In i.i.d.\ evaluation, GNN achieves 1.8$\times$ higher catch rate
than MLP (1.64\% vs 0.90\%, $p{=}0.0006$) across 20 held-out seeds, and scales to
$4\times$ larger clusters with only $1.1\times$ inference overhead vs
$4.3\times$ for LSTM.

The primary limitations and directions for future work are discussed
in \S\ref{sec:limitations}.  Full simulator, model code, and
experiment scripts are publicly available at
\url{https://github.com/subodhwandile/proactivehop}.
