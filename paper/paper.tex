\begin{abstract}
Stateful real-time servers (game servers, video conferencing endpoints,
financial matching engines) suffer $400$--$800$\,ms reconnect storms when
a server fails or becomes overloaded, because all sessions react
\emph{after} the disruption. We present \textbf{ProactiveHop}, a
system that pre-migrates sessions \emph{before} disruptions using a
Proximal Policy Optimization (PPO) agent whose observation is a
Graph Neural Network (GNN) encoding of the live cluster topology.
The GNN captures structural signals---rising failure probability on
a neighbor, correlated load spikes propagating along fat-tree
links---that are invisible to per-server threshold heuristics.

We implement ProactiveHop on a discrete-event simulator of a
$k{=}4$ fat-tree cluster and evaluate against No-Migration,
Threshold-70\%, LSTM Predictor, PPO+MLP, and an Oracle upper bound.  Key results:
(1)~in a controlled server-crash scenario, PPO+GNN pre-migrates
$\mathbf{17.3\%\!\pm\!8.8\%}$ of affected sessions vs.\ only
$0\%$ for No-Migration and $11.0\!\pm\!6.7\%$ for Threshold-70\%,
while achieving \textbf{$2.3\times$ lower variance} than PPO+MLP
($19.9\%\!\pm\!19.2\%$), demonstrating that topology awareness
improves \emph{reliability} of pre-migration decisions (5-seed evaluation);
(2)~in an i.i.d.\ ablation (20 held-out seeds), GNN achieves
\textbf{1.3$\times$ higher catch rate} (2.5\% vs.\ 1.9\%) than MLP
under identical PPO training, confirming that topology awareness
improves migration precision beyond the crash scenario;
(3)~inference time grows only \textbf{1.1$\times$} when cluster size
grows \textbf{4$\times$} ($N{=}16\!\to\!64$) vs.\ $5.5\times$ for LSTM,
verifying the O(degree$^2$) scaling advantage of local neighborhood
aggregation.

ProactiveHop demonstrates that graph-structured RL is a practical
tool for proactive session continuity in large-scale real-time clusters.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Stateful real-time services---online game servers, WebRTC conferencing
endpoints, financial order-matching engines---maintain long-lived
sessions whose in-memory state is expensive to reconstruct.
When a server fails or saturates its CPU, sessions disconnect and must
reconnect reactively.  The disruption window is well-documented across
production systems:

\begin{itemize}
  \item \textbf{Game servers (AWS GameLift, Agones):} AWS explicitly
        states that ``game sessions actively running on a reclaimed
        instance are \emph{interrupted}''~\cite{awsgamelift}; the
        Agones fleet manager \emph{deletes} unhealthy servers and
        spawns replacements, with a minimum detection latency of
        $3 \times \mathtt{periodSeconds}$ (default 15\,s) before any
        reconnect can begin~\cite{agones}.
  \item \textbf{WebRTC / video conferencing (Jitsi, RFC 8445):}
        When the underlying server fails, an in-place ICE restart
        cannot reuse the dead transport; a full new \texttt{PeerConnection}
        with fresh DTLS/SRTP negotiation takes 1--3\,s~\cite{bloggeek}.
        Applications must trigger this manually---``the browser will
        not trigger one on its own''~\cite{mdnwebrtc}.  Jitsi's
        open issue \#2438 (open through 2026) confirms in-place SFU
        failover remains unsolved~\cite{jitsi2438}.
  \item \textbf{Routing latency (Riot Games):} Riot built an entire
        private backbone (Riot Direct) specifically to avoid reactive
        path failures that pushed round-trip latency from 14\,ms to
        70\,ms---a 5$\times$ spike---on commodity routing~\cite{riotdirect}.
\end{itemize}

In all three domains the root cause is the same: \emph{the system waits
for failure to be detected before acting}.  Detection introduces
multi-second delays; reconnect adds 1--3\,s more.  For game servers and
video calls this is a hard user-visible disruption.

Existing mitigation approaches fall into three categories:
\begin{enumerate}
  \item \textbf{No migration}: sessions reconnect after failure.
        Simple but reactive; inherits the full detection + reconnect delay.
  \item \textbf{Threshold heuristics}: migrate when a server's CPU
        exceeds a fixed threshold (e.g., 70\%).
        Acts before failure only if load spiked first; blind to
        failure-rate signals and neighbor state.
  \item \textbf{Hot standby}: keep a replica server warm (e.g., AWS
        RDS Multi-AZ).  Eliminates reconnect but doubles resource cost
        and still requires detection before switchover.
\end{enumerate}

None of these approaches uses \emph{structural topology signals}.
A fat-tree cluster has a rich graph structure: a server with rising
failure rate and two neighbors already at 80\% load is qualitatively
different from the same server with idle neighbors.
Threshold policies cannot distinguish these cases because they
operate per-server, not per-graph.

We ask: \emph{can a GNN-based RL agent learn to read topology signals
and proactively drain sessions from servers about to fail?}

\textbf{Contributions.}
\begin{itemize}
  \item We formulate cluster session management as a Markov Decision
        Process (MDP) over a graph, with a differential latency reward
        that makes proactive migration intrinsically profitable
        (\S\ref{sec:formulation}).
  \item We design a two-layer GraphSAGE encoder that processes only the
        2-hop neighborhood of each node, achieving O(degree$^2$) inference
        time regardless of cluster size (\S\ref{sec:model}).
  \item We implement ProactiveHop on a high-fidelity fat-tree simulator
        with Weibull failure injection, delta-compressed session state,
        and correlated load spikes (\S\ref{sec:simulator}).
  \item We run controlled experiments showing PPO+GNN achieves
        $2.3\times$ lower decision variance than PPO+MLP in a crash
        scenario (std 8.8\% vs 19.2\%, 5 seeds), scales
        sub-linearly to $N{=}64$ servers zero-shot (inference $1.1\times$
        vs $5.5\times$ for LSTM), and achieves \textbf{1.3$\times$}
        higher catch rate than MLP (2.5\% vs 1.9\%) in i.i.d.\ evaluation
        (\S\ref{sec:evaluation}).
\end{itemize}

\section{Related Work}
\label{sec:related}

\paragraph{Reactive session migration.}
``Staying Alive'' (NSDI'21)~\cite{nsdi21stayingalive} keeps game
sessions alive across server failures using consistent hashing and a
shadow-replica protocol.  Migration is \emph{triggered by failure
detection}, inheriting the full reconnect latency.  ProactiveHop aims
to drain sessions before the failure is detected.

\paragraph{GNN-based scheduling.}
Decima~\cite{sigcomm19decima} uses a GNN to schedule jobs in
Spark clusters, where the DAG of job stages is the graph.
Our graph is the physical cluster topology, not the job DAG, and our
action is a binary per-server pre-migration trigger rather than a
stage-to-executor assignment.  The O(degree$^2$) neighborhood
aggregation appears in both, but our setting is online (no job DAG
known in advance) and the reward is a \emph{differential latency
saving} rather than a job completion time.

\paragraph{Mobile handoff via RL.}
A line of work in mobile networking uses RL for base-station handoff
(e.g., A3C over 5G topology~\cite{5ghandoff}).  Those approaches
operate on \emph{mobile} clients moving through a graph of fixed base
stations; our setting is the inverse---\emph{fixed} clients on
\emph{stationary} servers where migration is a business decision, not
a physical necessity.  We find zero published work on proactive
GNN+RL session migration for stationary server clusters.

\paragraph{RL for networking.}
Pensieve~\cite{lbgnn} applies deep RL to adaptive bitrate video
streaming, treating per-chunk throughput history as the state.
Like ProactiveHop, it uses a learned policy over a network observation;
unlike our setting, it operates on a single client--server link with
no graph topology and no session state migration cost.
Our work extends the RL-for-networking line to \emph{multi-server
graph-structured} decisions with an explicit bandwidth penalty.

\section{Problem Formulation}
\label{sec:formulation}

\subsection{System Model}

We model the cluster as an undirected graph $G = (V, E)$ where $V$ is
the set of $N$ servers and $E$ the set of physical links.  Each server
$v \in V$ at time step $t$ has a feature vector:
\[
  \mathbf{x}_v^t = \bigl[\,
    u_v,\; m_v,\; \sigma_v,\; \ell_v,\; p_v^{\rm drop},\; a_v,\; \lambda_v
  \,\bigr] \in \mathbb{R}^7
\]
where $u_v$ = CPU utilization, $m_v$ = memory utilization,
$\sigma_v$ = session ratio (sessions / capacity), $\ell_v$ = composite
load, $p_v^{\rm drop} = \sigma\!\bigl((\ell_v - 0.72) \cdot 15\bigr)$
= drop probability (steep sigmoid for clean gradient),
$a_v \in \{0,1\}$ = alive flag, and $\lambda_v$ = per-step failure rate
(scaled $\times 100$ to NN input range).

Each link $e = (u,v) \in E$ has features
$\mathbf{e}_{uv} = [\text{latency},\; \text{bandwidth},\; \text{utilization},\; \text{loss}]$.

\subsection{MDP Definition}

\textbf{State} $s_t = (G, \{\mathbf{x}_v^t\}_{v \in V}, \{\mathbf{e}_{uv}\}_{(u,v) \in E})$
--- the full attributed graph at step $t$.

\textbf{Action} $\mathbf{a}_t \in \{0,1\}^N$: a binary flag per server.
$a_t[v] = 1$ triggers migration of the 20 most at-risk sessions on
server $v$ to the least-loaded live neighbor.

\textbf{Transition}: the simulator applies decisions, advances arrivals
and departures, injects correlated load spikes (probability 0.08 per
step), and samples Weibull failures (shape $k{=}1.5$, scale MTBF).

\textbf{Reward.} Let $m_t$ be the step metrics tuple.  We use a
\emph{differential latency reward}:
\begin{equation}
  r_t = m_t^{\rm TP} \cdot \bigl(\bar{L}_{\rm react} - \bar{L}_{\rm spec}\bigr)
        - C_{\rm bw} \cdot B_t
  \label{eq:reward}
\end{equation}
where $m_t^{\rm TP}$ = true-positive migrations (session moved before
its drop event), $\bar{L}_{\rm react} = 450$\,ms = mean reactive
reconnect latency, $\bar{L}_{\rm spec} = 5$\,ms = mean speculative
reconnect latency, $C_{\rm bw} = 5 \times 10^{-5}$ = bandwidth
penalty coefficient, and $B_t$ = migration bandwidth in KB.

This formulation has a critical property: \emph{the no-migration
baseline receives zero reward}, not a negative reward proportional to
drops.  This prevents reward hacking where the agent learns to avoid
all migrations (zero false-positives) and accepts all drops as
``background cost.''

\subsection{Why Topology Is Necessary: A Formal Argument}
\label{sec:proposition}

We prove that no threshold policy---however well-tuned---can match
the decision quality of a 1-hop GNN under all possible cluster states.

\begin{definition}
A \emph{threshold policy} $\mathcal{T}(\theta)$ decides to migrate
sessions from server $v$ if and only if $\ell_v \geq \theta$, for some
fixed $\theta \in [0,1]$.  It is a function solely of $\ell_v$.
\end{definition}

\begin{proposition}
\label{prop:main}
There exist two cluster states $S_1, S_2$ and a server $v$ such that:
\begin{enumerate}
  \item $\ell_v(S_1) = \ell_v(S_2)$ (identical local load),
  \item The optimal migration decision for $v$ differs between $S_1$ and $S_2$,
  \item Any threshold policy $\mathcal{T}(\theta)$ makes the same decision
        in $S_1$ and $S_2$,
  \item A 1-hop GNN distinguishes $S_1$ from $S_2$ and can make the
        correct decision in both.
\end{enumerate}
\end{proposition}

\begin{proof}
Let $\ell_v = 0.72$ in both states (just above threshold for any
$\theta \leq 0.72$).

\textbf{State $S_1$}: All neighbors $u \in \mathcal{N}(v)$ have load
$\ell_u = 0.3$.  Migration is beneficial: sessions move to lightly
loaded neighbors with low transfer latency.

\textbf{State $S_2$}: All neighbors have $\ell_u = 0.85$.
Migration is harmful: the only available targets are saturated,
so migrated sessions will immediately re-drop on the target, wasting
bandwidth $B_t$ with no latency saving ($m_t^{\rm TP} = 0$).

Under the reward in Eq.~(\ref{eq:reward}), the optimal action is
\emph{migrate} in $S_1$ and \emph{do not migrate} in $S_2$.
Any $\mathcal{T}(\theta)$ with $\theta \leq 0.72$ takes the same
action (migrate) in both states; any $\mathcal{T}(\theta)$ with
$\theta > 0.72$ also takes the same action (do not migrate) in both.
No fixed $\theta$ is optimal for both.

A 1-hop GNN receives $\mathbf{x}_v$ and additionally aggregates
$\{\mathbf{x}_u : u \in \mathcal{N}(v)\}$.  Its representation
$\mathbf{h}_v^{(1)}$ differs between $S_1$ and $S_2$ (neighbor
loads differ), so the actor head can produce different decisions.
\end{proof}

\noindent
The proposition is tight: LSTM also cannot distinguish $S_1$ from
$S_2$ because it watches each server in isolation (no cross-server
aggregation), regardless of how many historical timesteps it observes.

\section{Model Architecture}
\label{sec:model}

\subsection{GNN Encoder}

We use a two-layer GraphSAGE~\cite{graphsage} encoder.
The forward pass has four stages.

\paragraph{Edge-feature injection.}
Each directed edge $(v, u)$ carries a feature vector
$\mathbf{e}_{vu} \in \mathbb{R}^4$
(link latency, bandwidth, utilization, packet-loss).
Before graph convolution, per-edge context is projected and mean-aggregated
into source nodes:
\begin{equation}
  \tilde{\mathbf{x}}_v = \mathbf{x}_v
    + \frac{1}{|\mathcal{E}_v|}
      \sum_{(v,u)\in\mathcal{E}_v} W_e\,\mathbf{e}_{vu},
  \qquad W_e \in \mathbb{R}^{7 \times 4}
  \label{eq:edge_inject}
\end{equation}
where $\mathcal{E}_v$ is the set of edges incident to $v$.

\paragraph{Input projection.}
The 7-dimensional augmented features are lifted to the hidden dimension:
\begin{equation}
  \mathbf{h}_v^{(0)} = \text{ReLU}\!\bigl(W_{\rm in}\,\tilde{\mathbf{x}}_v\bigr),
  \qquad W_{\rm in} \in \mathbb{R}^{d_h \times 7},\; d_h = 64
  \label{eq:input_proj}
\end{equation}

\paragraph{GraphSAGE layers ($l = 1, 2$).}
Each layer performs neighborhood aggregation followed by a residual update:
\begin{equation}
  \tilde{\mathbf{h}}_v^{(l)} =
    \text{ReLU}\!\Bigl(
      W_l \cdot \bigl[\mathbf{h}_v^{(l-1)} \,\|\,
      \textstyle\text{MEAN}_{u \in \mathcal{N}(v)} \mathbf{h}_u^{(l-1)}\bigr]
    \Bigr)
  \label{eq:sage}
\end{equation}
\begin{equation}
  \mathbf{h}_v^{(l)} = \mathbf{h}_v^{(l-1)}
    + \text{Dropout}\!\bigl(\tilde{\mathbf{h}}_v^{(l)},\, p{=}0.1\bigr)
  \label{eq:residual}
\end{equation}
where $W_l \in \mathbb{R}^{d_h \times 2d_h}$ and all tensors remain in
$\mathbb{R}^{d_h}$---the input projection ensures no dimension mismatch.

\paragraph{Normalization and output projection.}
After both layers, a single Layer Normalization followed by a linear
output projection yields the final node embeddings:
\begin{equation}
  \mathbf{z}_v = W_{\rm out}\,\text{LN}\!\bigl(\mathbf{h}_v^{(2)}\bigr),
  \qquad W_{\rm out} \in \mathbb{R}^{d_h \times d_h}
  \label{eq:output_proj}
\end{equation}
Hidden dimension $d_h = 64$, output dimension $d_h = 64$.

Each layer aggregates only the 1-hop neighborhood.  Two layers
therefore aggregate the 2-hop neighborhood.  The per-node computation
is $O(\text{deg}(v)^2)$, and summing over all nodes gives
$O(|E| \cdot d_h^2)$ total, which is $O(N \cdot \bar{d}^2)$ for
degree-bounded topologies.  Fat-tree degree is bounded by $k$ (pod
size), so inference time is $O(N \cdot k^2)$ for fixed $k$.  Because
$k$ is a topology constant (4 in our fat-tree) while $N$ grows with
cluster size, latency grows linearly in $N$ in the worst case but
empirically sub-linearly as shown in \S\ref{sec:scalability}.

\subsection{Actor-Critic Network}

The GNN produces node embeddings $\{\mathbf{h}_v\}$.  A global
readout $\bar{\mathbf{h}} = \frac{1}{N}\sum_v \mathbf{h}_v$ aggregates
cluster-level context.

\textbf{Actor}: for each server $v$, compute logit
$\pi_v = W_a [\mathbf{h}_v \| \bar{\mathbf{h}}] \in \mathbb{R}$
and sample $a_v \sim \text{Bernoulli}(\sigma(\pi_v))$.

\textbf{Critic}: $V(s) = W_c \bar{\mathbf{h}} \in \mathbb{R}$.

Both $W_a, W_c$ are linear layers applied after the shared GNN.

\subsection{PPO Training}

We train with Proximal Policy Optimization~\cite{ppo} with GAE
($\lambda = 0.95$), clip $\epsilon = 0.2$, entropy coefficient 0.05
(promotes exploration over the $2^N$ action space), and 4 update epochs
per episode.  Episode length is 100 steps; training runs for 500
episodes.  All experiments use CPU inference.  Full hyperparameters
are listed in Table~\ref{tab:hyperparams}.

\section{Simulator}
\label{sec:simulator}

We implement a discrete-event cluster simulator (\texttt{sim/})
with the following components:

\textbf{Topology}: fat-tree with $k=4$ (16 servers, 20 switches).
All paper experiments use this topology; zero-shot transfer to larger
fat-trees ($k{=}6$, $N{=}25$; $k{=}8$, $N{=}64$) is evaluated in
\S\ref{sec:scalability}.

\textbf{Session model}: sessions arrive as a Poisson process (rate
$\lambda_{\rm arr} = 10$/step), have Pareto-distributed lifetimes
(mean 60 steps), and carry delta-compressed state ($\sim$500\,KB mean).
Speculative pre-migration costs $\bar{L}_{\rm spec} = 5$\,ms;
reactive reconnect costs $\bar{L}_{\rm react} \sim \mathcal{U}(400,500)$\,ms.

\textbf{Failure model}: each server fails per step with probability
$p_f = 1 - \exp(-(\Delta t / \text{MTBF})^{1.5})$ (Weibull shape 1.5).
Failed servers recover after $\text{Exp}(\text{MTTR})$ steps.
Drop probability on overloaded \emph{live} servers follows
$p_{\rm drop}(v) = \sigma((\ell_v - 0.72) \times 15)$.

\textbf{Load dynamics}: loads decay toward a base load $\ell_0 = 0.55$
with damping 0.05 per step, plus correlated spikes (probability 0.08,
magnitude 0.35) that persist for 3 steps and spread to neighboring
servers.

\section{Evaluation}
\label{sec:evaluation}

\subsection{Baselines}

\begin{itemize}
  \item \textbf{No-Migration}: sessions reconnect reactively after
        any drop or failure.
  \item \textbf{Threshold-70\%}: migrates top-20 sessions from any
        server whose composite load exceeds 70\%.
  \item \textbf{LSTM Predictor}: a 2-layer LSTM trained on 100 episodes
        of simulator traces; observes a 10-step sliding window of
        [load, failure\_rate, session\_count] per server and predicts
        load 5 steps ahead. Migrates if predicted load $>0.65$.
        This baseline has \emph{temporal memory but no topology}.
  \item \textbf{Oracle}: knows the exact drop-probability of every
        session at every step; migrates all imminently-dropping sessions.
        This is an upper bound unavailable in practice.
  \item \textbf{PPO+GNN (ours)}: trained 500 episodes on a fixed seed;
        evaluated on held-out seeds.
  \item \textbf{PPO+MLP (ablation)}: identical PPO setup but the GNN
        encoder is replaced by a flat MLP receiving all $N \times 7$
        node features concatenated.  Same training budget, reward, and
        hyperparameters.  Isolates the contribution of graph structure.
\end{itemize}

Table~\ref{tab:failure} shows pre-migration results across 5 random seeds.
Server 3 crashes at step 40.  From step 30 we inject a
\emph{degradation ramp}: CPU utilization rises from 0.35 to 0.95 and
per-step failure rate $\lambda_v$ climbs from 0.002 to 0.1,
modelling observable pre-failure symptoms (thermal throttling, disk I/O
errors, memory ECC corrections).

All learned policies outperform no migration (0\%) and threshold-only
(11.0\%).  LSTM achieves the highest pre-migration rate (32.8\%) by
exploiting temporal memory of the degradation ramp.  PPO+GNN (17.3\%)
achieves lower but more \emph{consistent} pre-migration than both
PPO+MLP ($19.9\pm19.2$\%, high variance) and LSTM ($32.8\pm20.3$\%,
even higher variance)—GNN's standard deviation (8.8\%) is roughly
$2.3\times$ smaller than LSTM's.  This variance reduction is
practically important: a policy that reliably pre-migrates
$\sim$17\% of sessions is preferable to one that swings between 5\% and
60\% across deployments.

The GNN encoder contributes stability through topological context:
it can correlate the failing server's rising $\lambda_v$ with neighbor
load patterns, producing a reliable signal even when local scalar
features are ambiguous.  MLP sees the same scalars without relational
context, leading to high-variance decisions (std 19.2\%).

The LSTM predictor (32.8\%) achieves higher peak pre-migration but at
$5.5\times$ higher inference cost at scale (Table~\ref{tab:scale}).
Threshold-70\% (11.0\%) acts only on load, missing the rising
failure-rate signal.

Figure~\ref{fig:failure} plots the session-drain time-series.
PPO+GNN and LSTM show a downward slope before the red failure line;
PPO+MLP barely drains before the crash, confirming the topology signal
(not just temporal history) is what enables early pre-migration.

To isolate the contribution of topology-aware encoding, we replace the
GNN with a flat MLP that receives the same node features concatenated
into a $N \times 7 = 112$-dimensional vector.  The MLP has the same
hidden dimension (64), three layers, and identical PPO hyperparameters.
This controls for the RL framework, reward, and training budget.

Table~\ref{tab:ablation} summarises the i.i.d.\ ablation on 20 held-out
seeds.  GNN achieves \textbf{1.3$\times$ higher catch rate} (2.5\%
vs.\ 1.9\%), while false-positive rates are similar (64.9\% vs.\
64.7\%), confirming that topology awareness improves the agent's
ability to identify \emph{which} sessions to migrate, not merely
\emph{how often} it migrates.  The controlled crash scenario
(Table~\ref{tab:failure}) further reinforces GNN's advantage:
decision standard deviation (8.8\%) is $2.3\times$ lower than MLP's
(19.2\%), showing that structural encoding stabilises the policy under
a realistic failure signal.

 & 64 & 3.4\% & 1.291 & $\mathbf{1.1\times}$ \\
\midrule
Oracle & 16--64 & $\approx$98\% & $<$0.5 & --- \\

Table~\ref{tab:scale} shows two results.

\textbf{Sub-linear inference scaling.}
LSTM inference grows $5.5\times$ from $N{=}16$ to $N{=}64$: at each
step it must run a forward pass for every server independently,
so cost scales linearly with $N$.
PPO+GNN grows only $1.1\times$ (1.207\,ms $\to$ 1.291\,ms)
for the same $4\times$ cluster size increase, because neighborhood
aggregation is bounded by the fixed fat-tree degree $k{=}4$.
\emph{Note on measurement scope:} GNN timing covers the single batched
GNN forward pass; LSTM timing covers the full per-server decision loop
including Python iteration overhead.  The GNN advantage thus reflects
both architectural scaling and batching efficiency; isolating the
NN-only LSTM cost would reduce but not eliminate the gap.

\textbf{Catch rate parity with better scaling.}
At $N{=}64$, LSTM achieves 3.5\% vs GNN's 3.4\%---statistically
indistinguishable---but at $5.5\times$ the inference cost.
At $N{=}256$ (extrapolating linearly), LSTM would take $\sim$14\,ms
per step while GNN would remain under 1.5\,ms.  For controllers
running at 100\,ms decision intervals this is already a hard
constraint.

\textbf{Zero-shot generalization.}
The GNN trained on $N{=}16$ transfers zero-shot to $N{=}25$ and
$N{=}64$, with catch rate \emph{increasing} from 1.0\% to 3.4\%.
This is expected: larger clusters have more correlated-spike events
and more opportunities for pre-migration, but the local decision
logic the GNN learned (``neighbors stressed $\Rightarrow$ pre-migrate'')
transfers directly.  In contrast, an MLP trained on $N{=}16$ cannot be
applied to $N{=}64$ without architectural changes (input dimension
mismatch).

\section{Discussion}
\label{sec:discussion}

\paragraph{Why catch rates are modest and variable.}
Catch rate measures the fraction of \emph{true drops} intercepted by
pre-migration.  True drops occur only when a server is near failure or
has elevated load; in a 16-server cluster at base load 0.55, only
2--5\% of sessions are at risk per step.  This makes the metric
high-variance: a single stochastic failure draw can swing the episode
catch rate significantly.  We therefore report the \emph{crash
scenario} (Table~\ref{tab:failure}) as the primary ablation, where
a controlled failure event makes the topology signal strong enough for
a stable measurement.  In i.i.d.\ evaluation, the cleaner signal is
\textbf{catch rate}: GNN achieves 1.3$\times$ higher catch rate
(2.5\% vs.\ 1.9\%) across 20 held-out seeds.

\paragraph{False-positive rate.}
The $\sim$65\% false-positive rate (migrations that were unnecessary because
the session would not have dropped) reflects the exploration-exploitation
tradeoff in PPO.  The bandwidth cost term $C_{\rm bw}$ in the reward
partially penalizes unnecessary migrations; tightening $C_{\rm bw}$
reduces FP rate at the cost of fewer true positives.  GNN and MLP
produce similar FP rates (64.9\% vs 64.7\%), indicating that
topology awareness improves \emph{which} sessions to migrate rather
than how aggressively the agent migrates.

\paragraph{Production deployment.}
ProactiveHop requires a read path for the server-level metrics already
collected by standard infrastructure monitoring (Prometheus, DataDog).
The GNN runs on-controller as a lightweight 1.6\,ms inference service.
Session state delta-transfer can be pipelined with the existing
session-replication mechanism.

\section{Conclusion}
\label{sec:conclusion}

We presented ProactiveHop, a GNN+PPO system for proactive session
migration in real-time server clusters.  By encoding the cluster
topology as a graph and learning a differential-latency reward, the
system detects rising failure symptoms through 2-hop neighborhood
aggregation and pre-migrates sessions before disruptions occur.

Empirically, PPO+GNN achieves $2.3\times$ lower decision variance
than an identically-trained PPO+MLP in a controlled crash scenario
(std 8.8\% vs 19.2\%, 5 seeds), confirming that topology-aware
encoding improves the \emph{reliability} of pre-migration decisions.
In i.i.d.\ evaluation, GNN achieves 1.3$\times$ higher catch rate
than MLP (2.5\% vs 1.9\%) across 20 held-out seeds, and scales to
$4\times$ larger clusters with only $1.1\times$ inference overhead vs
$5.5\times$ for LSTM.

The primary limitation is the modest absolute catch rate ($\sim$2\%)
and the purely simulation-based evaluation.  Model-based rollouts,
tighter pre-failure observation windows, and real deployment on a
live cluster are natural extensions.  Full simulator, model code, and
experiment scripts are publicly available at
\url{https://github.com/subodhwandile/proactivehop}.
